Operational: prevent automatic NO_SHOW and allow re-creating SUS demands/queues after terminal states

Summary
- Fixes: prevent recovery jobs from auto-marking trips NO_SHOW when queue is WAITING_DISPATCH/PENDING_DISPATCH.
- Sus-import: allow creating new OperationalQueue when existing queue is terminal (NO_SHOW/COMPLETED/CANCELLED) and treat terminal-only OperationalDemand as re-creatable for new imports.

Files changed
- apps/api/src/modules/operational-flow/operational-flow.service.ts
  - recoverStaleTrips: skip auto-NO_SHOW if latest queue is WAITING_DISPATCH/PENDING_DISPATCH.
  - forceCompleteRoute: skip force-NO_SHOW for trips whose latest queue is WAITING_DISPATCH/PENDING_DISPATCH.
- apps/api/src/modules/sus-import/services/sus-import.service.ts
  - Add SKIP_DEMAND / SKIP_QUEUE logs (diagnostic).
  - CREATE_NEW_QUEUE_AFTER_TERMINAL: create new queue when existing is terminal.
  - CREATE_NEW_DEMAND_AFTER_TERMINAL: treat demand with only terminal queues as eligible for new import (update metadata and allow queue creation).
